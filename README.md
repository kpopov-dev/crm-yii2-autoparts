# CRM оптового отдела магазина автозапчастей

CRM для оптового направления крупного магазина автозапчастей «АвтоДеталь»: контрагенты
(СТО, таксопарки, дилерские центры, розничные точки), заказы на поставку с воронкой,
задачи менеджеров, отчётность и асинхронная обработка бизнес-событий через RabbitMQ.

Проект собран как демонстрация production-подхода к backend-разработке на Yii2: слоистая
архитектура, транзакции, ручной SQL с осознанной работой по индексам, паттерн Transactional
Outbox, идемпотентные консьюмеры, RBAC и покрытие доменной логики тестами. Предметная
область — оптовые отгрузки запчастей, но код намеренно не завязан на неё: домен вынесен
в отдельный слой и меняется независимо от инфраструктуры.

```
PHP 8.2 · Yii2 · MySQL 8 · RabbitMQ 3.13 · Vue 2.7 · Vuex · Vue Router · Vite · Docker · Nginx
```

## Возможности

**Контрагенты**
Оптовые покупатели с сегментацией: независимые СТО, официальные дилеры, таксопарки,
грузовые автопарки, розничные точки, шиномонтаж и автомойки. Поиск по названию и ИНН,
карточка со статистикой отгрузок, условия оплаты и отсрочки, архивирование,
привязка к ответственному менеджеру.

**Заказы на поставку**
Канбан-доска с перетаскиванием карточек по воронке: заявка → подбор и наличие →
коммерческое предложение → согласование условий → отгружена или отказ. Табличное
представление с фильтрами и сортировкой, карточка заказа с полной историей стадий,
автогенерация номера вида `ZP-2026-00001`, конечный автомат стадий с проверкой
допустимости переходов.

**Задачи менеджеров**
Проверка остатков на складе, подбор аналогов по VIN, запрос сроков у поставщика,
выставление счетов и контроль дебиторки: исполнитель, срок, привязка к заказу,
подсветка просроченных, смена статуса, переназначение.

**Отчёты**
Воронка заказов, конверсия и средний чек отгрузки, выручка по месяцам, рейтинг
менеджеров со средним циклом заказа от заявки до отгрузки, сводка по просроченным задачам.

**Асинхронные события**
Смена стадии заказа, отгрузка, отказ и назначение задачи публикуются в RabbitMQ.
Консьюмеры создают уведомления менеджерам и инкрементально обновляют витрину
дневной статистики.

**Права доступа**
RBAC на базе `yii\rbac\DbManager`. Менеджер видит только своих контрагентов, заказы и
задачи, администратор — все данные и отчёты в разрезе менеджеров.

```
                                     │ REST, JWT в Authorization
                        ┌────────────▼─────────────┐
                        │  Nginx → PHP-FPM         │
                        │  Yii2, модуль crm        │
                        └────────────┬─────────────┘
                                     │
        ┌────────────────────────────┼──────────────────────────┐
        │                            │                          │
  ┌─────▼──────┐          ┌──────────▼─────────┐      ┌─────────▼────────┐
  │ Controller │──────────► Service (домен,    │──────► Repository        │
  │ + Form     │          │ транзакции, права) │      │ (чистый SQL)      │
  └────────────┘          └──────────┬─────────┘      └─────────┬────────┘
                                     │                          │
                          ┌──────────▼─────────┐          ┌─────▼─────┐
                          │ outbox_message     │          │  MySQL 8  │
                          │ (в той же трансакции)         └───────────┘
                          └──────────┬─────────┘
                                     │  worker: php yii outbox/relay
                          ┌──────────▼─────────┐
                          │  RabbitMQ          │
                          │  topic crm.events  │
                          └──────────┬─────────┘
                     ┌───────────────┴───────────────┐
             ┌───────▼────────┐             ┌────────▼───────┐
             │ crm.notifications            │ crm.analytics  │
             │ уведомления    │             │ daily_stat     │
             └────────────────┘             └────────────────┘
```

Поток запроса: контроллер принимает HTTP, форма валидирует и нормализует вход, сервис
выполняет бизнес-правила в транзакции, репозиторий обращается к базе. Наружу отдаются
готовые массивы-DTO, ActiveRecord за пределы сервисного слоя не выходит.

Подробнее — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Быстрый старт (Docker)

Нужны только Docker и Docker Compose. Всё остальное поднимется в контейнерах.

```bash
git clone https://github.com/<ваш-логин>/crm-yii2-autoparts.git
cd crm-yii2-autoparts
make init
```

`make init` последовательно: создаст `.env` из примеров, соберёт образы, поднимет
контейнеры, установит зависимости, применит миграции, создаст роли и наполнит базу
демо-данными.

Если `make` в системе нет, те же шаги вручную:

```bash
cp .env.example .env
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env

docker compose build
docker compose up -d

docker compose exec php composer install
docker compose exec php php yii migrate --interactive=0
docker compose exec php php yii migrate --migrationPath=@yii/rbac/migrations --interactive=0
docker compose exec php php yii rbac/init
docker compose exec php php yii seed/init
```

После запуска доступны:

| Сервис | Адрес |
| --- | --- |
| Веб-интерфейс «АвтоДеталь» | http://localhost:5173 |
| REST API | http://localhost:8080/api |
| Проверка состояния API | http://localhost:8080/api/health |
| RabbitMQ Management | http://localhost:15672 (crm / crm) |
| MySQL | localhost:3307 (crm / crm) |

Перед первым запуском обязательно замените `JWT_SECRET` в `backend/.env` на длинную
случайную строку:

```bash
openssl rand -hex 32
```

## Ручная установка без Docker

Требуется PHP 8.1+ с расширениями `pdo_mysql`, `intl`, `mbstring`, `sockets`, `bcmath`,
MySQL 8.0+, RabbitMQ 3.9+, Composer 2 и Node.js 18+.

```bash
cd backend
cp .env.example .env
# отредактируйте DB_HOST, DB_USER, DB_PASSWORD, RABBITMQ_HOST, JWT_SECRET
composer install
php yii migrate --interactive=0
php yii migrate --migrationPath=@yii/rbac/migrations --interactive=0
php yii rbac/init
php yii seed/init
php -S localhost:8080 -t web
```

В отдельных терминалах запустите фоновые процессы:

```bash
cd backend && php yii outbox/relay
cd backend && php yii consume/notifications
cd backend && php yii consume/analytics
```

Фронтенд:

```bash
cd frontend
cp .env.example .env
npm install
npm run dev
```

Бэкенд отдаёт только JSON и не использует asset-бандлы Yii, поэтому bower-зависимости
фреймворка (`jquery`, `inputmask`, `punycode`, `yii2-pjax`) отключены через секцию
`replace` в `backend/composer.json`. Благодаря этому `composer install` работает с
обычного Packagist, без плагина `fxp/composer-asset-plugin` и без репозитория
asset-packagist.

Настройка боевого сервера на Ubuntu описана в [docs/DEPLOY_UBUNTU.md](docs/DEPLOY_UBUNTU.md).

## Демо-доступы

| Роль | Логин | Пароль |
| --- | --- | --- |
| Администратор | admin@crm.local | Admin123! |
| Менеджер | manager@crm.local | Manager123! |

Сидер создаёт пятерых пользователей, 36 контрагентов из восемнадцати сегментов
автобизнеса, 140 заказов с историей стадий и задачи с разными сроками, чтобы отчёты
и воронка сразу были заполнены реалистичными данными.

Номенклатура в демо-данных собирается из шестнадцати товарных групп (тормозные колодки
и диски, фильтры, масла, аккумуляторы, амортизаторы, ремни ГРМ, сцепления, шины и
другие) с реальными брендами и правдоподобными оптовыми ценами, поэтому суммы заказов
и средний чек выглядят как в живой системе.

## Технические решения

**Слоистая архитектура и внедрение зависимостей.**
Контроллеры получают сервисы через конструктор, сервисы зависят от интерфейсов, а не
от реализаций. Привязки описаны в `backend/config/container.php`, поэтому заменить
источник данных или брокер можно без правки бизнес-логики.

**SQL без ORM.**
Все выборки для списков и отчётов написаны вручную через `createCommand` с
именованными параметрами. Индексы спроектированы под конкретные запросы, порядок
колонок в составных индексах соответствует порядку условий, сортировка приходит только
из белого списка, поиск использует префиксный `LIKE`, чтобы не терять индекс.
Канбан-доска выбирает по 50 заказов на стадию одним запросом с оконной функцией
`ROW_NUMBER() OVER (PARTITION BY stage)`. Разбор запросов и планов — [docs/SQL.md](docs/SQL.md).

**Транзакции и блокировки.**
Смена стадии заказа читает строку через `SELECT ... FOR UPDATE`, проверяет допустимость
перехода, обновляет заказ, пишет запись в историю и складывает событие в outbox —
всё в одной транзакции. Гонки при одновременном перетаскивании карточки исключены.

**Transactional Outbox.**
Событие сохраняется в таблицу `outbox_message` в той же транзакции, что и изменение
данных. Отдельный воркер `php yii outbox/relay` забирает пачку записей через
`FOR UPDATE SKIP LOCKED` и публикует в RabbitMQ, ведёт счётчик попыток и текст ошибки.
Данные и события не могут разъехаться, даже если брокер недоступен.

**Идемпотентные консьюмеры.**
Перед обработкой сообщения его идентификатор вставляется в `processed_message` с
уникальным индексом по паре `message_id + consumer`. Повторная доставка отбрасывается,
а при ошибке обработки запись удаляется и сообщение уходит в dead-letter очередь.

**Конечный автомат стадий.**
`StageTransitionPolicy` разрешает движение по воронке только на один шаг вперёд или
назад, закрытие заказа — с любой открытой стадии, а возврат отгруженного заказа
обратно в работу запрещает. Правила покрыты юнит-тестами и переиспользуются интерфейсом: фронтенд
рисует только те кнопки перехода, которые вернул сервер.

**Безопасность.**
JWT с проверкой срока жизни, пароли через bcrypt cost 12, RBAC на уровне действий,
белые списки полей сортировки и фильтров, отключённая эмуляция подготовленных
выражений PDO, единый формат ошибок API без утечки стектрейсов в production.

## Команды консоли

```bash
php yii migrate                      применить миграции
php yii rbac/init                    создать роли и разрешения
php yii rbac/assign-all              переназначить роли пользователям
php yii seed/init                    наполнить демо-данными
php yii seed/flush                   очистить все таблицы
php yii user/create <email> <пароль> <ФИО> [роль]
php yii user/reset-password <email> <пароль>
php yii outbox/relay                 воркер публикации событий
php yii outbox/once [limit]          разово опубликовать пачку
php yii outbox/status                сколько событий ждёт публикации
php yii consume/notifications        консьюмер уведомлений
php yii consume/analytics            консьюмер витрины статистики
```
